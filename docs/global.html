checkRowIds(rows, optopt) → {Object|null}

Description:

  • 外部同步(syncAndReplaceTabs)之主鍵檢核(R-SYNC-1 第③項), 純函數, 不讀寫資料庫

    只檢查「有給主鍵」之列: 主鍵為非空字串或有限數字者; 空字串、未給、NaN、±Infinity 或其他型別視為未給, 由 w-serv-orm 補主鍵, 不在此限. 依序檢查, 回報第一個違反: (a) xss: 字串主鍵經 wsemi clearXSS 會被改寫(同 w-serv-orm getMapOrm.mjs 之 getItemsIdXSS 判準; 其於 insert 時整批拒絕, 而同步已先 delAll) (b) bytes: UTF-8 位元組超過 maxIdBytes (c) dup: 同批已出現同一主鍵 (d) group: 資料庫中同主鍵之列屬他群組(insert 為主鍵已存在即略過, 不會搬移). 重複與群組之比對以 String(id) 正規化: w-serv-orm 1.1.11 起字串型主鍵欄之有限數字主鍵存為其字串形式(123 存為 '123'、回應之 id 為 '123'), 故 123 與 '123' 為同一主鍵(2026-10-14 定案; 原「數字主鍵語意待確認、保守視為同鍵」之註記作廢).

createLockSave(cst) → {function}

Description:

  • 有副作用之寫入路徑(如清單儲存 updateUsersList / updateTokensList / updateIpsList)之雙擊防護(後端, ADR-034)

    以「操作:操作者 id」於 wsemi cacheSt 原子占位執行 fn, 同一操作者之同一操作處理中再送出即 reject 錯誤 key (預設 'saveInProgress', 可以 opt.errKey 指定; 皆為 i18n key, 見 procLang); 不同操作者、不同操作互不影響; fn 之 reject 原樣 bubble; fn 結束(含失敗)即釋放. 第 2 次不排隊執行: 其內容與第 1 次相同, 排隊後再寫一次會把第 1 次剛建立之列當修改覆寫 (依序重送另由各專案之資料層檢查擋, 如 SSO procCore.updateTabItems 之新增列檢查回 'saveNewRowExists'). operatorId 可為操作者 id 或「操作者 id + 列識別」(只擋同一列之連發, 同批其他列不受影響).

  • 資料通道(w-serv-webdata 之表操作與資料同步)之選項, 交給 WServHapiServer 展開使用(R-DC-1, ADR-038)

    w-serv-webdata 1.1.7 起 useDbOrm=true 時 authorizeExec 為必填(未給即建構拋錯, w-serv-hapi 1.1.6 起同步拋出); procOrm 不做授權(w-serv-orm 1.1.9 起), 表操作之授權在開放處——本模組:

ormFail(opt) → {function}

Description:

  • procOrm／ORM 之失敗轉為語系鍵(R-ERR-1, ADR-038)

    w-serv-orm 之 procOrm 失敗時 reject 英文訊息字串(如 'failed to save data: id[...]', 1.1.8 起), 直呼 ORM(woItems)者則可能 reject Error; 兩者皆不是本套件之語系鍵, 原樣交出會使前端 $transErr 只能回退 anUnexpectedErrorOccurred、外部呼叫端收到非 key 之字串(CLAUDE.md「錯誤一律回 key」). 故於呼叫 ORM 處以 .catch(ormFail(...)) 改回語系鍵: 寫入類(save/insert/del/delAll)→ 'saveWriteFail'(同 w-web-sso 用語: 部分變更可能已生效)、 讀取類(select)→ 'getDataError'; 原文入 srLog 之 orm 欄供查因. 只用於 ORM 呼叫之 .catch: 本套件自身之 key(如 lockSave 之 saveInProgress)不經此處, 故不需辨識「已是語系鍵」. 記錄規則(權杖外洩防護之 srLog 規則, ADR-033): 字串(w-serv-orm 自產之英文訊息, 只含主鍵或位置)截 200 字; Error 只記名稱與代碼, 不記 message.

submitGuard() → {Object}

Description:

  • 送出類操作之前端雙擊防護核心 (與 Vue / store 無關, 供單元測試; 由 mUI 之 runSubmit 與 updateLoading 使用, ADR-034)

    • run(key, fn, opt): 同 key 之送出流程進行中(自觸發起至流程結束, 含結果訊息框開啟期間)再觸發即略過. 按鈕之滑鼠與鍵盤 Enter、輸入框之 Enter 等入口共用同一狀態. opt.pm 為 WButtonChip / WButtonCircle 之 promiseUnlock 鎖(click 事件之 msg.pm), 於 releaseBtnLocks()(全頁 loading 關閉, 即請求結束) 或流程結束時釋放; 被略過之觸發亦立即釋放其 pm, 否則該按鈕永久鎖住. fn 收到 unlock 函數: 流程需先開確認框者於開框前呼叫, 按鈕鎖只涵蓋請求期間(確認框背後之按鈕不顯示載入圖示), 重入仍由流程狀態擋. opt.hold 為函數, 輸入流程結果, 回傳 true 時保持占位與按鈕鎖(如登入成功轉址, 頁面即將離開).
    • releaseBtnLocks(): 釋放進行中流程所登記之按鈕鎖, 流程狀態不變(結果訊息框開啟期間之重入仍擋).
    • isRunning(key): 查詢 key 是否進行中.

    為何需要: 全頁 loading(WDialog)不搶焦點, 只擋滑鼠, 鍵盤事件仍送達背後之按鈕與輸入框; 按鈕鎖若於 handler 第一行即解除, 鍵盤連按照樣送出(2026-09-29 實測).
