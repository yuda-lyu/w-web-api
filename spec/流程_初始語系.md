# 初始語系流程（server 注入）

## 觸發

後端 `srv.mjs` 以 `settings.json` 的 `language` 啟動；`WWebApi` 啟動時把 `{language}` 注入 `dist/index.html`（`index.tmp` 為不可變模板），使 `window.___pmwperm___.language` 帶該語系。瀏覽器載入頁面（不帶 URL `?lang=`）時，前端 `getLang`（優先序 `URL ?lang=` > `window.___pmwperm___.language` > store）取得此 server 注入語系，**初始畫面即以該語系渲染**。此流程驗「由 server 端 `settings.json` 之 `language` 設定決定初始畫面語系」：未帶 `?lang=` 載入時，前端 `getLang` 回落至 `window.___pmwperm___.language`（即 server 注入值），初始畫面即呈現該語系。

> 註：getLang 之 window 須排在 store 之前——store.state.lang 預設為非空 `'eng'`，若 store 在前會 shadow 掉 window 注入值。

## 重要流程

依使用者實際觀察順序：連線中（進站第一眼）→ 已登入（連上、登入成功，主畫面資料未到之過場）→ 主畫面。
三狀態皆「不帶 `?lang=`」，純靠 server 注入語系；前兩者後端 kpLang 尚未載入，文字由前端內建字典（mUI `kpFallback`）依注入語系顯示——這是「server 注入初始語系」最關鍵的觀察點。各狀態以攔截特定請求懸置之方式凍結，方能穩定截圖。

- **E2E-001**
  - title: 連線中畫面即呈現該語系文字
  - description: 後端以 `settings.language=<lang>` 啟動，開 `?token=sys`（不帶 `?lang=`）。**攔截登入檢查請求（getUserByToken）使其懸而不答** → `loginSuccess` 不觸發 → 連線狀態停在「連線中（csIng）」。連線中文字（Connecting…/連線中…）由 `kpFallback` 依注入語系顯示。預期含該語系連線中文字、不含另一語系、尚未進已登入/主畫面。
  - flow:
    - 測試資料：base seed；server 設定 `language` 設為本輪語系。
    - 操作：以該語系重啟後端 → 攔截 getUserByToken（併攔連線通道）懸置 → 開 `<baseUrl>/?token=sys` → 畫面停連線中。
    - 驗證：
      1. 語意：`window.___pmwperm___.language` 等於本輪語系；含該語系「Connecting」/「連線中」、**不含**另一語系連線中文字、**不含**「Logged in」/「已登入」與主畫面分頁。
      2. 視覺：紅框框住「連線中」文字，遮罩旋轉 spinner（SVG `<animate>` 非決定性）；baseline `test/pics/init/init-{eng,cht}-E2E-001-connecting.png`（pixelmatch 反鋸齒感知 + maxDiffPixels 容差，非 byte-exact）。
    - 雙語：eng / cht 各一輪。
    - 清理：純展示無 DB 副作用；本檔全跑完以預設 `settings.json` 重啟後端還原語系；起跑前還原 base seed。

## 執行流程

```

002  組 opt：language 取自 stApp.language（預設 'eng'）  [srv.mjs:37]
        以 opt（含 language）建構 WWebApi 實例  [srv.mjs:101]
003  WWebApi 啟動產生入口頁：讀 index.tmp（無則退回 index.html）  [server/WWebApi.mjs:592-604]
        將內容之 {language} 佔位符取代為 language，寫出 index.html  [server/WWebApi.mjs:608-609]
004  瀏覽器載入 index.html：window.___pmwperm___.language 即注入之 language（佔位 {language} 已被取代）  [public/index.html:23-27]
005  main.js 掛載 App、啟動 WServHapiClient 長連線（useWaitToken）  [src/main.js:53-99]
006  App.vue beforeMount 呼叫 setLang(null)（交 getLang 解析）  [src/App.vue:57]
        setLang：lang 為空 → 呼叫 getLang()  [src/plugins/mUI.mjs:140-146]
            getLang 優先序一：URL ?lang=（本流程不帶，isestr 判空後略過）  [src/plugins/mUI.mjs:100-112]
            getLang 優先序二：window.___pmwperm___.language（= server 注入語系），validLang 檢核  [src/plugins/mUI.mjs:117-122]
            getLang 優先序三：store.state.lang（預設非空 'eng'，故 window 須排其前，否則 store 會 shadow window 注入值）  [src/plugins/mUI.mjs:125-131]
        setLang 依解析語系寫入 store.lang、取 kpLang[lang] 更新 kpText、廣播 forceUpdate  [src/plugins/mUI.mjs:151-171]
        kpLang 尚未載入時：getKpText 查無 kpText → 回退 kpFallback[key][lang]，連線中/已登入文字即依注入語系顯示  [src/plugins/mUI.mjs:184-189]
```

## 參數來源

| 概念 | 來源（優先序）| 流程影響 |
|---|---|---|
| 初始語系 | `settings.json` `language` → WWebApi 注入 `index.html` → `window.___pmwperm___.language` | 不帶 `?lang=` 時的初始畫面語系 |
| 前端語系解析 | `getLang`：URL `?lang=` > window 注入（server 預設）> store | URL 最高（功能流程用）；window 為 server 注入初始語系；store 為 fallback（預設 'eng'，故須排 window 之後）|
| e2e 指定 server 語系 | `restartBackend(genTempSettings({ language }))` | 以臨時 settings 重啟後端、改變注入語系 |

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **粒度**：本流程只驗「server 注入語系（`settings.language`）→ 初始畫面語系」單一機制；所有 case 一律不帶 `?lang=`。
- **邊界**：dev server（未注入 `{language}`）時 window 為模板符號 → `validLang` 退回 eng；e2e 一律於 11005（dist，已注入）執行。
- **順序**：server 注入（啟動期）先於前端 getLang（載入期）。getLang 中 window 須排 store 前（store 預設非空 'eng' 會 shadow window）；執行期語系切換以 `setLang(明確值)` 直接寫入、其後無 `setLang(null)` 故能持久（不被 window 覆蓋）。
- **契約**：`index.tmp` 為不可變模板（含 `{language}`）；多次切換 server 語系須保留 `index.tmp`，否則 `index.html` 注入後無佔位符可再注入。
